# Contributing

## Key takeaway

Change the smallest justified Practice or source-aligned object and preserve evidence boundaries.

## Summary

Contributions should improve adult learning guidance, source faithfulness or verification without increasing false authority. The independent adult audience and Practices-first architecture remain explicit.

## Before changing content

1. Read AUTHORING, ALIGNMENT, SCOPE and the target Practice with its direct dependencies.
2. Identify the source-defined meaning, the local adaptation and the proposed improvement separately.
3. Inspect the relevant source passage; preserve context, comparators, outcomes and access limitations. Do not replace a missing passage with an invented locator.
4. Keep original coaching workflows inside Practices and use academic names for faithful scholarly objects.

## Source and learning review

A source may be suitable for a definition but not for an efficacy claim. General learning research, a custom classroom AI tutor and a generic independent-adult chat are different contexts. Do not treat technical CI success as scientific approval. Any future reviewed status needs an actual reviewer and claim-level review record; this release remains provisional.

## Pull requests

Use a change branch and a PR. Explain the task, sources actually inspected, affected summaries, actual tests and remaining limits. Merge only when separately authorized and appropriate checks pass. Do not disable checks or refresh hashes merely to produce green CI.

## Privacy and access

Keep completed learner records outside the public repository. Do not commit API keys, restricted source excerpts or recording data. Preserve access accommodations in evaluation designs. Stop a workflow when it exceeds the agreed educational scope.

## Reproduce

Run the five commands in CHECKS.md. Regenerate navigation from canonical files, review affected summaries and only then accept the dependency snapshot. Keep upstream tool copies pinned and record any proposed tool changes separately.
