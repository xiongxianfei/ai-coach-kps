# Evaluation of AI Assisted Learning

## Key takeaway

Judge a learning claim using recorded task conditions, independent evidence where appropriate, and explicitly limited inferences.

## Summary

This Practice asks what an adult actually demonstrated, not whether the AI session felt impressive. It produces an evaluation record distinguishing assisted performance, independent performance, delayed retention and changed-context application. The six stages are recommended; credible criteria, access arrangements and consent are prerequisites. This is a low-stakes local evaluation workflow, not a validated psychometric instrument or randomized causal experiment.

## Entry and boundaries

Use for learner-owned, low-stakes evaluation. The learner can decline or stop. This is not a clinical assessment, grading authority or causal-impact certification. Keep private records out of public version control and inspect task correctness before interpreting a score. No automatic mastery metric is assumed.

## One learning claim to evaluate

Select **one bounded claim** about a capability under declared resources, such as an independent explanation on an unfamiliar task. Reuse available task records instead of imposing a redundant test. If the claim concerns later retention or changed-context application, leave it pending until the necessary observation actually occurs. Conclude with one justified next check or learning task. The [lesson and task guide](../guides/learning-workflow.md) supports task scoping but does not define a universal mastery threshold.

## Stage1 Specify the evaluation question and criterion

1. State **one bounded claim** you want to examine: immediate task capability, retained knowledge, transfer to a specified context, or the contribution of a coaching design. These are different questions.
2. Define relevant response features and allowed resources before seeing the result. Include what would count against the proposed interpretation.
3. Select tasks capable of exposing the target. A multiple-choice recognition question is not interchangeable with producing a justified solution.
4. State the stakes and obtain the learner's agreement. Do not use this local workflow for credentials, clinical judgment or consequential personnel decisions without suitable qualified procedures.

**Assessment triangle in use**: write the target capability (cognition), the task response to collect (observation), and how that response would support or limit the claim (interpretation). These elements constrain one another; they are not an automatic scoring pipeline.

## Stage2 Document baseline assistance and exposure

1. Preserve any available baseline exactly, including help and prior practice. When no baseline exists, say so; do not reconstruct one from memory or an AI impression.
2. Distinguish access accommodations from answer-generating help. Record hints, shown solutions, partial code, reference access and whether the same item appeared before.
3. Record the AI product/model version when known, date, source material and design choices that could affect results. Unknown fields remain unknown.
4. Identify possible confounds such as changed difficulty, extra study time, repeated items, motivation or a corrected answer key. A longer coaching transcript is not a measure of learning.

Never edit the initial response to match the later correction. Baseline and post-instruction tasks should be meaningfully comparable, but simple similarity does not create a controlled experiment.

## Stage3 Collect an independent task response

1. Choose an appropriate task with a verified criterion, preferably not an already revealed solution. Declare the permissible tools and supports before the attempt.
2. Hide answer-generating cues for an independent check. Retain access accommodations and any resources that are legitimately part of the target capability.
3. Preserve the original response before consulting feedback. If hints or answers arrive early, mark the attempt as assisted or contaminated for this purpose; do not report an independent success.
4. Evaluate against the criterion, using a source, deterministic check or competent human when needed. An AI-only evaluation remains unverified evidence, even if confidently expressed.

If a test cannot be collected, the output is pending. Missing data must not become zero, failure or success. No numerical cutoff is provided as a universal definition of competence.

## Stage4 Observe a later and a changed context task

1. Choose and actually conduct a later check when the claim concerns retention. Record elapsed time and intervening study; a future date in a plan is not a delayed observation.
2. Choose a changed-context task when transfer is claimed. Explain the relevant difference in representation, constraints or required reasoning. A near variation does not establish far transfer.
3. Keep assistance conditions visible for each task, not just the first. Record any criterion uncertainty or access constraint.
4. Interpret immediate, delayed and changed-context responses separately. Do not infer the unmeasured outcomes from the measured one.

**Local evidence categories, not scores**

| Record | What it may support | What remains open |
|---|---|---|
| Correct assisted response | Task completion with the stated support | Independent capability |
| Independently checked immediate response | Capability on that task at that time | Retention |
| Checked response after a known interval | Retention for the target and conditions | Wider transfer |
| Checked changed-context response | Application to that specified context | Universal generalization |

These rows are interpretation aids, not standardized scientific categories of mastery.

## Stage5 Compare explanations without overclaiming causality

1. Compare the actual records with the original criterion. Note contradictions, uncertainty and whether the task sampled enough of the intended capability.
2. Distinguish a practical decision from a causal conclusion. "This routine is worth continuing for me" can be a provisional decision without proving that AI caused an observed change.
3. Consider extra practice time, easier tasks, prior familiarity, source corrections and other plausible explanations. A pre/post comparison in one learner does not isolate the treatment effect.
4. Read AI-specific studies in their settings. Kestin's structured college tutor and Bastani's high-school designs differ in population, topic, controls and timing. Their findings do not imply that all coaching prompts help or harm adults.
5. Choose whether better evidence is necessary for the decision. Use appropriate study design and qualified research support before making general causal claims about effectiveness.

The retained evidence is intentionally mixed: promising contextual results and failure risks both constrain the application. Citation count cannot replace a comparison of designs and outcomes.

## Stage6 Record the conclusion and next decision

1. Write what was demonstrated, conditions of assistance and verification, actual intervals, and the scope of changed-context evidence.
2. List what was not measured. Keep an unresolved classification when timing, source accuracy or assistance history is missing.
3. Choose **one next action**: continue a bounded task, alter one support, investigate a prerequisite, seek expert feedback or stop. Preserve the reason and invite the learner to challenge the interpretation.
4. Keep personal responses private. Publish only de-identified or constructed examples when rights and consent permit, never fabricated observations.
5. Review the interpretation after new evidence rather than freezing a learner label. If a generalization changes, update the linked local explanation, not the original event history.

**Conclusion template**

```text
Question and criterion: [fill]
Observed responses and actual help: [fill]
Reference or verification basis: [fill]
Supported inference and its scope: [fill]
Retention and changed-context evidence: [fill or not observed]
Alternative explanations and missing information: [fill]
Next decision, rationale and optional future check: [fill]
```

A complete evaluation report may conclude that evidence is insufficient. That is a valid output, not a reason to invent a final grade.

To revise a [two-level plan](concept-mapping-and-instructional-sequencing-with-ai.md), associate the observation with a goal, map version and stable stage ID. An overview can be accurate while the learner cannot yet apply it; independently reconstructing one relation does not establish mastery of the panorama. Evaluate the selected capability before advancing or revising a stage, and preserve the record underlying that decision.

## Record checker and its limits

The optional [record checker](../tools/check_record.py) reports internally inconsistent declarations and missing evidence. It does not determine answer correctness, diagnose a learner, infer an effect size or establish that any instruction worked. See [learning notes](../guides/learning-notes.md) for the schema and private-use guidance.

## Stopping and fallback

Stop when the reference cannot be verified, the learner withdraws, the task exceeds the agreed stakes or privacy cannot be preserved. A human expert or a different assessment may be needed. Preserve the uncertainty rather than lowering the evidence standard just to complete a workflow.
