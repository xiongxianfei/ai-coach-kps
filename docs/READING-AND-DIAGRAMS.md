# Reading navigation and diagrams

## Key takeaway

Use direct local links and simple explanation aids without requiring a special viewer or image quota.

## Summary

This guide combines the navigation profile and the selective visual-explanation policy. Tables and text remain appropriate where an image would not resolve ambiguity.

## Navigation and reading

These conventions help readers move between independently complete documents; a link is not a replacement for necessary guidance.

## Reading routes

[Practice map](../generated/PRACTICE-MAP.md) is the learner entry. [INDEX](../generated/INDEX.md) lists academic objects by role. [EVIDENCE-MAP](../generated/EVIDENCE-MAP.md) traces source support and application limits. [TERMINOLOGY-MAP](../generated/TERMINOLOGY-MAP.md) records canonical naming. [REVIEW-QUEUE](../generated/REVIEW-QUEUE.md) identifies remaining inspection and evaluation.

## Link procedure

1. Prefer a relative file link for an entire object.
2. For a stage, include the full lowercase heading fragment, such as #stage1-define-a-learning-goal-and-constraints.
3. After renaming a heading, update the stage map, metadata and incoming links together.
4. Test the actual reader when rendering matters; structural validation is not a click test in every Markdown application.

The generated graph is a dependency view, not a model of human cognition or a compulsory reading sequence. No plugin or iframe is required.

## Selective visual explanations

Diagrams are used when they clarify a relationship, not to satisfy an illustration quota.

## Current audit

The five Practices use point-of-use decision and evidence tables. Their branch conditions and next actions are readable without graphics. Cognitive Apprenticeship is represented as a four-dimension table, not a newly invented six-stage cycle. The Assessment Triangle has a text triad with explicit noncausal edge meaning. The source and reference declarations remain in the owning Models.

These relationships are sufficiently compact for text, so no D2/SVG assets are claimed or required in this release. This is a selective-format decision consistent with the Core contract's allowance for simple text diagrams and tables; it is not a claim that visual instruction is ineffective.

The overview Practice adds a compact text flow and local tables. Conceptual connections, selected-goal links, stage requirements and feedback decisions are explained separately. The text layout does not imply that knowledge forms a prerequisite tree. No new rendered diagram or image-effectiveness claim is made.

## Future image procedure

1. Identify an actual ambiguity the diagram would resolve and document its owner and scope.
2. Use D2 for a useful editable diagram and keep the generated SVG alongside it; retain attribution and labels for synthetic examples.
3. Register owner, reason and files in diagrams.json and include actual pinned-render checks before claiming freshness.
4. Inspect the rendered result for legibility and preserve the text explanation. Do not hand-edit generated SVG or imply an effect-size chart is measured when its data are invented.

No D2 renderer check has been performed for this text-only slice, because no D2 artifact is included.
